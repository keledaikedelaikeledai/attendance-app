# AGENTS.md

## Stack

Nuxt 4 + Vue 3, Bun runtime, PostgreSQL (Drizzle ORM), Better Auth, Nuxt UI, Leaflet maps, i18n (en/id).

## Commands

```bash
bun install                # install deps (bun is the package manager)
bun run dev                # dev server at localhost:3000
bun run build              # production build
bun run lint               # ESLint (@antfu/eslint-config)
bun run lint:fix           # auto-fix lint

bun run db:generate        # generate SQL migrations from schema
bun run db:push            # push schema to DB (no migration file)
bun run db:migrate         # apply pending migrations
bun run db:studio          # Drizzle Studio GUI

bun run auth:schema        # regenerate Better Auth schema from server/utils/auth.ts

bun test                   # run all tests (uses bun:test, NOT vitest/jest)
bun test tests/local-date.test.ts   # single test file

bun run k6:run             # load test with k6
bun run seed:last-month    # seed sample attendance data
```

No typecheck script exists. No CI lint/test pipeline — only a Docker publish workflow on push to `master`.

## Architecture

- `app/` — Nuxt app: pages, layouts, composables, components, middleware
- `server/` — Nitro server: API routes under `server/api/`, shared utils under `server/utils/`, DB schemas under `server/database/schemas/`
- `server/api/auth/[...all].ts` — catch-all Better Auth handler (all auth routes go through here)
- `server/api/attendance/` — clock-in/out, geofence check, reports, shift selection
- `server/api/admin/` — admin-only endpoints (attendance, geofences, shifts, users)
- `server/database/schemas/auth-schema.ts` — auto-generated by `bun run auth:schema`; do not hand-edit
- `server/database/schemas/schema.ts` — hand-written tables (shift, attendanceDay, attendanceLog, geoFence)
- `locales/` — i18n JSON files (lazy loaded by @nuxtjs/i18n)

## Auth model

Routes are protected by default via `app/middleware/auth.global.ts`. Guest-only pages use:
```ts
definePageMeta({ auth: { unauthenticatedOnly: true } })
```
Admin routes use `app/middleware/admin.ts` which checks `session.user.role === 'admin'`.

Better Auth plugins: `username()`, `admin()`. Client at `app/utils/auth.ts` mirrors with `usernameClient()`, `adminClient()`.

## Auto-imports — critical

**Server utils (`useBetterAuth`, `useDb`, etc.) are auto-imported by Nitro.** Do NOT add explicit imports for them in server route files — this causes route registration and import-resolution failures.

When writing server code, use relative imports for sibling `server/` files (e.g., `import { x } from '../utils/local-date'`). Do not use `~` or `@` aliases in server code — they resolve differently in Nitro build.

Client-side composables (`useAttendance`, `useAttendanceTime`, `useConfirmation`) and Nuxt built-ins (`useFetch`, `useRouter`, `useState`, `definePageMeta`) are also auto-imported.

## Date/time handling

Dates are stored as `YYYY-MM-DD` text strings (local calendar dates, NOT UTC dates). The client sends its timezone offset via `getTimezoneOffset()` semantics. Key helpers in `server/utils/local-date.ts`:

- `localNowYmdFromOffset(now, tzOffsetMinutes)` — converts current time to local date string
- `localDateTimeToUtcMs(ymd, hh, mm, tzOffsetMinutes)` — converts local wall-clock to UTC epoch ms
- `addDaysYmd(ymd, days)` — safe date arithmetic on YMD strings

`server/utils/time.ts` has `normalizeTimestampRaw()` which handles DB rows that may store seconds vs milliseconds vs ISO strings.

## Geofence

Geo-fences support two types: `point` (center + radius) and `polygon` (array of [lat,lng] pairs). Interaction modes: `disallow`, `allow`, `allow_with_comment`. Schema in `server/database/schemas/schema.ts`.

## ESLint rules of note

Uses `@antfu/eslint-config`. Key overrides:
- `vue/max-attributes-per-line`: max 3 on single line, 1 on multiline
- `antfu/if-newline`: off
- `no-console`: error (except `warn`, `error`, `info`, `time`, `timeEnd`)

## Docker

Multi-stage Dockerfile: Bun build stage with `--preset bun`, runtime stage copies `.output` + migrations. Timezone hardcoded to `Asia/Jakarta`. Port defaults to 3000.

`docker-compose.yml` runs: attendance-app, PostgreSQL, cloudflared tunnel. Migrations are NOT auto-applied in the container — run `bun run db:push` against the target DB separately.

## Tests

Tests live in `tests/` and use `bun:test` (import `describe`, `expect`, `test` from `bun:test`). Currently covers `attendance-reconcile.ts` and `local-date.ts` utilities only.
